# Включение инструментов модуля: шаги администратора

Когда модуль разработчика установлен и отдаёт манифест ([box-module.md](box-module.md)), администратор портала
делает четыре вещи.

## 1. Проверить, что методы видны

Под администратором открыть `/rest/<манифест>` (например `demo.mcp.tools`): ответ — список инструментов.

## 2. Выдать приложению область модуля

Приложению **shef.cowork** на портале выдаётся область, в которой модуль зарегистрировал методы (например
`demo_notes`): права локального приложения, либо настройки приложения, если оно установлено иначе. Без области портал
отвечает `insufficient_scope`, и инструментов нет.

Новые права приходят вместе с новым токеном, поэтому **сотрудникам нужно войти заново**.

## 3. Вписать манифест в «Модули портала»

Приложение shef.cowork → «Настройки» → «Модули портала»: имя метода-манифеста, по одному на строку (запятая тоже
разделяет), до 20 манифестов.

- Группа «Модули портала» включается администратором; выключена — инструментов модулей нет ни у кого.
- Манифест может назвать только методы своего вендора, поэтому в список вписывается именно метод-манифест
  (`demo.mcp.tools`), а не отдельные инструменты.

## 4. Открыть запись тем, кому она нужна

Инструменты `kind: write` и `kind: delete` видны только сотрудникам из списка «Кто может менять данные» в тех же
настройках. Пустой список — запись только у администраторов. Остальные сотрудники видят только чтение.

Подтверждение удаления: перед удалением сервер спрашивает сотрудника в окне AI-клиента; метод модуля зовётся только
после «да». Клиент, который не умеет задавать такие вопросы, инструментов удаления не получает. Если у инструмента
задан `confirmRead`, сотрудник видит в вопросе саму запись.

## Как убедиться

1. Сотрудник открывает AI-клиент, подключённый к shef.cowork: новые инструменты в списке (список манифеста помнится до
   5 минут).
2. Вызов инструмента проходит от имени сотрудника; при отказе модуля агент показывает его текст.
3. Что-то не появилось: проверьте по порядку — метод-манифест отвечает на `/rest/…`; область выдана; сотрудник вошёл
   заново; манифест вписан без опечатки; у записи — сотрудник в списке «Кто может менять данные»; в журнале сервера
   нет строк `"kind":"manifest"` с причиной отказа записи.
