# Облачный портал и приложение

Сервер shef.cowork не вызывает ваш сервер напрямую. Он вызывает **REST-метод портала**: сначала метод-манифест, затем
метод инструмента, оба токеном вошедшего сотрудника (`https://<портал>/rest/<метод>`). Из этого следует всё ниже.

## Что известно точно

- Манифест и методы инструментов должны быть доступны на портале как REST-методы с **общим вендором** (первый
  сегмент имени: манифест `acme.mcp.tools` может назвать только `acme.*`).
- Методам нужна область прав. Приложению shef.cowork на портале должна быть выдана область, к которой относятся
  методы; без неё портал отвечает `insufficient_scope`, и инструментов нет (см. [enable.md](enable.md)).
- Все правила манифеста — те же, что для коробки: [box-module.md](box-module.md), [rules.md](rules.md). Проверка —
  `node tools/manifest-check.mjs`.

## Чего в документации REST нет

Документация REST Битрикс24 (`bitrix-tools/b24-rest-docs`) описывает добавление своих методов в REST **только для
коробочной версии**: статья `settings/cloud-and-on-premise/on-premise/custom-methods.md`. Для облачного портала
способа зарегистрировать собственный метод с произвольным вендором (`acme.notes.search`) в ней нет, а методы вашего
собственного сервера в REST портала не появляются. Поэтому:

- **Подтверждённый путь — коробочный модуль** ([box-module.md](box-module.md)).
- Для облака дать агенту свои функции через манифест можно, только если нужные методы уже доступны на портале
  как REST-методы с общим вендором и областью. Своего метода приложение облака в портале не создаёт, и этот
  репозиторий не обещает такого пути. Если ваш случай иной, сначала проверьте на тестовом портале, что
  `https://<портал>/rest/<метод-манифест>` отвечает списком инструментов от имени сотрудника.

Для самой интеграции приложения с порталом (OAuth, области прав, установка) — разделы REST-документации
`settings/oauth/*` и `api-reference/scopes/permissions.md` в `bitrix-tools/b24-rest-docs`.

## Что подготовить, если метод на портале есть

1. Область прав метода и приложение shef.cowork: администратор добавляет область в права приложения и просит
   сотрудников войти заново.
2. Манифест по правилам [box-module.md](box-module.md#манифест): `method` — только вендор манифеста, `input` без
   `$ref`, у `delete` — `confirmRead`.
3. Запись — только отдельными инструментами `write` и `delete`; открывает запись администратор портала
   ([enable.md](enable.md)).
4. Проверка: `/rest/<манифест>` под администратором, затем инструменты в AI-клиенте.
