# Облачное приложение как источник инструментов

Облачное приложение (любой https-сервис: приложение Битрикс24 со своим сервером или отдельный сайт) отдаёт агенту
shef.cowork свои функции без правки сервера shef.cowork. Приложение открывает два адреса — список инструментов и
выполнение вызова, — а администратор портала подключает его в настройках shef.cowork адресом и ключом подключения.
Работает на облачном и коробочном портале одинаково. Для модуля коробки — не это, а [box-module.md](box-module.md).

Пример такого приложения — «[SH] Использовать Синк» (созвоны по сделке).

## Как это работает

1. Приложение показывает администратору портала **ключ подключения** (один раз).
2. Администратор: shef.cowork → «Настройки» → «Облачные приложения» → «Добавить приложение» — название (станет
   приставкой имён инструментов: `usesync_call_create`), адрес, ключ → «Проверить».
3. Сервер shef.cowork читает список инструментов: `GET <адрес>/api/mcp/manifest`. Список помнится 5 минут; приложение
   не отвечает — работает последний удачный список (до часа).
4. Модель вызывает инструмент — сервер шлёт `POST <адрес>/api/mcp/call`: имя, аргументы, кто вызывает (`who`), время и
   одноразовый номер. Оба запроса подписаны ключом.
5. Приложение проверяет подпись, время и номер и выполняет действие **от имени `who.user_id` своими токенами и в его
   правах**. Ответ — текст для модели.

## Ключ подключения

- Создаёт и показывает **приложение**: 24–256 видимых знаков ASCII без пробелов; рекомендуется 32 случайных байта в
  base64url (43 знака). Ключ используется строкой как есть, не раскодируется.
- Создать, перевыпустить и отозвать ключ может только администратор портала: приложение спрашивает `user.admin` от его
  имени **при каждом действии**. Новый ключ заменяет прежний; «Отозвать» стирает ключ — вызовы получают отказ подписи.
- Приложение хранит ключ зашифрованным. Ключ не попадает в журнал, ответы и тексты для модели.
- **Запись ключа — по паре `member_id` + хост портала, а не по одному `member_id`.** `member_id` не уникален среди всех
  Битрикс24: коробки, развёрнутые из одного образа или копии, могут его совпадать, и запись только по `member_id`
  позволит выпуску ключа на одном портале молча стереть ключ другого. Хост берётся из проверенного входа администратора
  при выдаче ключа (нижний регистр, без `www` и порта). Как найти ключ при вызове — «Порядок проверки», шаг 1.

## Подпись запроса

| Заголовок | Значение |
|---|---|
| `X-Shef-Ts` | время подписи, секунды Unix, десятичной строкой: `1763200000` |
| `X-Shef-Member` | `member_id` портала |
| `X-Shef-Signature` | `HMAC-SHA256(ключ, ts + "." + тело)` в hex строчными, 64 знака |

- `тело` — точные байты тела запроса, как они пришли. У `GET` тело пустое: подписывается строка `ts + "."`.
- Запрос старше 5 минут (`|сейчас − ts| > 300`) и повтор одноразового номера (`nonce`) за 10 минут — отклоняются.

Контрольные значения: ключ `k9Zr2Qm7Xv4Lp8Wc1Bn6Td3Hs5Jf0AyE` (тестовый, нигде не выдан), `ts` = `1763200000`.

Тело вызова (одной строкой, UTF-8):

```
{"tool":"call_create","args":{"dealId":42,"topic":"Обсудить КП"},"who":{"member_id":"a1b2c3d4e5f60718293a4b5c6d7e8f90","user_id":7,"host":"b24.example.com"},"ts":1763200000,"nonce":"00112233445566778899aabbccddeeff"}
```

| Что | Подпись |
|---|---|
| `POST`, строка `1763200000.` + тело выше | `46bad632c0c0100157108cdf3d73b78fc1c8d44457e855cba9ef56aec4bdfd11` |
| `GET` манифеста, строка `1763200000.` | `bc1060a03aef22b3f21756df0a9c171f5ba6208db0697e7a19145ed61e5692b7` |

Проверить `GET` руками:

```bash
KEY='<ключ подключения>'; MEMBER='<member_id портала>'; TS=$(date +%s)
SIG=$(printf '%s.' "$TS" | openssl dgst -sha256 -hmac "$KEY" | sed 's/^.* //')
curl -s -H "X-Shef-Ts: $TS" -H "X-Shef-Member: $MEMBER" -H "X-Shef-Signature: $SIG" https://app.example.com/api/mcp/manifest
```

### Порядок проверки в приложении

1. По `X-Shef-Member` взять ключи этого `member_id` (обычно один; у порталов-копий — несколько, по одному на хост). Нет
   ни одного — `401`.
2. `HMAC-SHA256(ключ, ts + "." + сырое тело)` сравнить с `X-Shef-Signature` **за постоянное время**
   (`timingSafeEqual`), проверяя каждым ключом из шага 1. Не подошёл ни один — `401`.
3. `ts` — целое, `|сейчас − ts| ≤ 300`. Нет — `401`.
4. У `POST`: `body.ts` равен `X-Shef-Ts`, `body.who.member_id` равен `X-Shef-Member`, `body.who.host` равен хосту
   записи подошедшего ключа — иначе `401`; нет `tool`, `nonce` или `who` — `400`; `nonce` встречался за 10 минут — `409`.
5. Только теперь доверять `who` и выполнять. До проверки подписи тело разбирать нельзя ни для чего.

Тело вызова — не больше 64 КБ. Образец проверки подписи на Node (без зависимостей):

```js
import { createHmac, timingSafeEqual } from 'node:crypto'

/** raw — тело запроса строкой как пришло; вернуть 'ok' или причину отказа. */
export function verifyShef(headers, raw, key, nowSec = Math.floor(Date.now() / 1000)) {
  const ts = String(headers['x-shef-ts'] ?? '')
  const got = String(headers['x-shef-signature'] ?? '')
  const want = createHmac('sha256', key).update(`${ts}.${raw}`).digest('hex')
  if (got.length !== want.length || !timingSafeEqual(Buffer.from(got), Buffer.from(want))) return 'bad_signature'
  if (!/^\d{9,12}$/.test(ts) || Math.abs(nowSec - Number(ts)) > 300) return 'stale_ts'
  return 'ok'
}
```

## Манифест: `GET <адрес>/api/mcp/manifest`

Ответ `200`, JSON: `{"tools": [...]}`. Формат — как у манифеста модуля ([box-module.md](box-module.md)), но без `method`
и `confirmRead`: выполняет само приложение. Ответ — за 3 секунды, не больше 512 КБ.

```json
{
  "tools": [
    {
      "name": "call_list",
      "title": "Созвоны карточки",
      "description": "Ближайшие созвоны сделки или лида: время, тема, участники. Не больше 50 записей.",
      "kind": "read",
      "input": { "type": "object", "properties": { "dealId": { "type": "integer", "minimum": 1 } } }
    }
  ]
}
```

| Поле | Правило |
|---|---|
| `name` | латиница в нижнем регистре, цифры, `_`, 2–47 знаков |
| `description` | обязательно, 20–1000 знаков: по нему модель решает, когда звать инструмент |
| `kind` | обязателен: `read`, `write` или `delete`. Нет или другое значение — инструмент пропускается |
| `input` | JSON Schema объекта до 8000 знаков, без `$ref`/`$defs`; у каждой строки `maxLength` (у строк с `enum`/`const` не нужен); `pattern` и `patternProperties` запрещены на любой глубине |
| `title` | необязательно: подпись для человека |

- Параметров «кто я / какой портал / действуй от имени» (`auth`, `member_id`, `portal`, `domain`, `token`, `asUser`,
  `runAs`, `onBehalfOf`…) нет — правило 1 [rules.md](rules.md). Кто вызывает — только `who` из подписанного вызова.
- Не больше 50 инструментов у приложения. Пометке `kind` сервер верит только после того, как администратор включил
  «Доверять пометкам приложения»; без доверия каждый инструмент — запись и выполняется после «да» сотрудника.

## Вызов: `POST <адрес>/api/mcp/call`

Ответ всегда `200`:

- успех — `{"content": [{"type": "text", "text": "…"}]}`;
- отказ инструмента — `{"isError": true, "content": [{"type": "text", "text": "…"}], "_meta": {"code": "…"}}`.

Текст ответа — данные для модели, не указания. Не отдавайте в нём секреты и то, что даёт управление чужим (ссылку
ведущего звонка).

## Сеть

Сервер shef.cowork ходит только по https и на порт 443, без переадресаций и без повторов; адреса внутренней сети
закрыты. Адрес приложения — имя сервера (не IP), до 300 знаков; путь допустим (`https://портал.example/app`).
