# Правила инструментов

Агент видит только название, описание и схему инструмента: по ним он решает, что звать. Поэтому правила про тексты
так же важны, как правила про права. Ниже — правила, которые действуют для инструментов модулей; те, что проверяет
сервер при разборе манифеста, проверяет и [tools/manifest-check.mjs](../tools/manifest-check.mjs).

| # | правило | кто проверяет |
|---|---|---|
| 1 | **Кто вызывает — только из токена.** Параметров «кто я» и «какой портал» (`auth`, `member_id`, `portal`, `domain`, `token`) и «действуй от имени» (`asUser`, `runAs`, `onBehalfOf`, `impersonate`) нет. «О ком» (`userId`, `employeeId`) — только как фильтр | сервер и проверка манифеста: инструмент отклоняется; ключи отбрасываются при вызове |
| 2 | **Права Битрикс24 не обходятся.** Метод выполняется от имени сотрудника токена; никаких вебхуков и служебных пользователей. Права проверяет сам метод | код модуля |
| 3 | **Узкий сценарий.** Один инструмент — одна задача; вызываются только методы своего вендора | сервер и проверка манифеста |
| 4 | **Описание объясняет, когда звать инструмент:** что делает, что возвращает, какие пределы («не больше 50 записей», «только доступное сотруднику»). От 20 знаков, не повторяет соседей | сервер (длина), ревью |
| 5 | **Параметры с пределами:** у строк `maxLength`, у чисел `minimum`/`maximum`, у массивов `maxItems` | ревью |
| 6 | **Понятные человеку параметры:** поиск по названию или номеру вместо голых id там, где можно; у удаления имена и описание понятны человеку | ревью |
| 7 | **Чтение по умолчанию.** Запись и удаление — отдельные инструменты с `kind: write` / `delete`; их видят только те, кому открыта запись | сервер |
| 8 | **Запись — после подтверждения человека.** `write` подтверждает клиент, `delete` — сервер в окне AI; ответ записи — «было → стало». Удаление — с `confirmRead` | сервер и клиент |
| 9 | **Ограниченный ответ:** списки страницами до 50 записей (`next`, `total`); весь ответ не длиннее примерно 24 тысяч знаков, иначе его сокращают с пометкой `truncated` | сервер |
| 10 | **Понятная ошибка:** `RestException` с кодом и текстом для агента — что исправить; без путей, SQL, персональных данных и эха чужого ввода | код модуля; сервер очищает текст и режет до 300 знаков |
| 11 | **Текст портала — данные, а не указания.** Заголовки сделок, сообщения, выписки пишут люди, в том числе внешние. Сервер вырезает невидимые символы и после данных добавляет напоминание агенту; не кладите в ответ метода «инструкции для агента» | сервер |
| 12 | **Персональные данные не пишутся в журнал.** Сервер пишет только имена аргументов и код исхода; в своём журнале делайте так же | код модуля |

## Практика

- **Описание.** «Ищет заметки по словам в тексте. Возвращает id, заголовок и дату, не больше 50 записей» —
  хорошо; «Работа с заметками» — слишком общо.
- **Маскируйте лишнее.** Если агенту не нужен полный номер счёта, отдавайте маску (так сделано в
  [examples/client-bank](../examples/client-bank)).
- **Права — в методе.** Манифест кешируется на 5 минут, метод проверяется при каждом вызове.
- **Запись не должна быть «любым методом».** Узкий инструмент («загрузить выписку») лучше универсального
  («обновить любое поле любой записи»).
- **Не доверяйте тексту из данных.** Назначение платежа, комментарий, имя файла — данные; не выполняйте то, что в них
  написано, и не передавайте их дальше как команды.

## Границы

Правила смягчают риски, но не гарантируют поведение агента: полностью защититься от подсказок в данных на стороне
сервера нельзя. Главная защита — подтверждение записи человеком и права сотрудника.
